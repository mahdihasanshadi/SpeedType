## PHASE 1 — Core typing engine, accounts & speed curve (13 features)

### 6. Database schema — auth, TypingTest, UserSettings

Add to `.env.local`:
```bash
DATABASE_URL=
```

> **Prompt**
> Read `database-schema.md`. Create `prisma/schema.prisma` for migrations `001_auth`,
> `002_typing_tests`, and `003_user_settings` exactly as specified — the standard Auth.js
> `User`/`Account`/`Session`/`VerificationToken` shape plus `TypingTest` and `UserSettings`. Run
> `pnpm db:push` against the Neon dev database and confirm it succeeded.

Test: open Prisma Studio, confirm every table exists with the right columns. Commit.

### 7. Auth — email/password + Google OAuth + guest mode

Add to `.env.local`:
```bash
NEXTAUTH_SECRET=
NEXTAUTH_URL=http://localhost:3000
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
```

> **Prompt**
> Build Auth.js v5 with a Credentials provider (bcrypt-hashed passwords) and Google OAuth, using
> the Prisma adapter and the schema from step 6. Build custom-themed signup and login screens per
> `design-system.md` and `ui-stack.md` — no default NextAuth UI. Unauthenticated visitors must
> still be able to take a full typing test as a guest — no forced signup wall on the core loop
> (`CLAUDE.md` rule 5).

Test: sign up via email/password and via Google, confirm both create a working session that
survives a page reload; confirm a signed-out visitor can still complete a test. Commit.

### 8. Design system implementation

> **Prompt**
> Implement the complete `design-system.md` token set (if not already fully wired in step 5),
> build the `ThemeToggle` component (system preference decides only on first visit with no saved
> choice, then the choice persists per-user), and retheme every shadcn component pulled so far to
> these tokens — nothing should still show shadcn's default zinc palette. This is the foundation
> every later screen builds on; get it exactly right before continuing.

Test: toggle theme, reload, confirm it persists; visually check contrast in both light and dark on
a real screen, not just the color picker. Commit.

### 9. Typing test engine core

> **Prompt**
> Build the typing engine per `ux-flows.md` and `ui-stack.md`: word/quote passage generation in
> `lib/texts/`, the Zustand store (`store/typing-store.ts`) tracking the keystroke log, current
> index, and timer, and `lib/wpm.ts` implementing the Net WPM / Raw WPM / Accuracy / Consistency
> formulas exactly as specified in `ux-flows.md` — character for character, no deviation. This file
> is what every stat in the app depends on; unit-test it against hand-computed fixtures before
> moving on.

Test: type a known passage with deliberate errors, hand-compute the expected WPM/accuracy, confirm
`lib/wpm.ts` matches exactly. Commit.

### 10. Test UI — caret, live highlighting, timer/word-count modes

> **Prompt**
> Build the test screen per `ui-stack.md`'s "typing test surface" section: per-character `<span>`s
> carrying `pending`/`correct`/`incorrect` state, a Framer Motion-animated caret sliding between
> character positions, a hidden always-focused input (works on mobile to summon the on-screen
> keyboard), and the minimal stat readout that fades in only after the first keystroke. Support
> time modes (15/30/60/120s) and word-count modes (10/25/50/100), plus punctuation and numbers
> toggles. Esc or a visible Restart control resets instantly, no page reload.

Test: run a full test in every mode on desktop and at 375px width; type a fast burst and confirm
zero dropped keystrokes. Commit.

### 11. Results screen

> **Prompt**
> Build the results screen per `ux-flows.md` Flow 2 — Net WPM as the `text-stat` headline, Raw WPM,
> Accuracy, Consistency, and the correct/incorrect/extra/missed character breakdown, with a
> 200–300ms spring transition in from the test screen. "Next test" restarts with the same settings
> and a fresh passage.

Test: complete a test, confirm every displayed stat matches `lib/wpm.ts`'s output for that exact
run. Commit.

### 12. Save test results — logged-in + guest local storage

> **Prompt**
> Build `POST /api/tests` per `api-conventions.md`'s route pattern. Call it optimistically the
> instant a test ends for logged-in users — never block the results render on it, silently retry
> once on failure, surface a non-blocking toast only if the retry also fails. For guests, save to
> local storage capped at 20 entries (oldest evicted) exactly as `ux-flows.md` Flow 2 describes,
> with the "sign up to keep this" banner.

Test: complete a test logged in, confirm the row appears in the database; complete 21 tests as a
guest, confirm exactly the most recent 20 remain in local storage. Commit.

### 13. Test history page

> **Prompt**
> Build `GET /api/tests` (paginated, newest first) and the history page listing date/mode/WPM/
> accuracy per past test. Every user is free-tier for now (Subscription doesn't exist until Phase
> 2) — apply the 90-day retention window from `database-schema.md`'s data-retention note to every
> user's query.

Test: save more than one page of tests, confirm pagination works and nothing older than 90 days
appears. Commit.

### 14. Speed curve chart

> **Prompt**
> Build `SpeedCurveChart` with Recharts per `ux-flows.md` Flow 3 and `ui-stack.md`'s charting
> rules — WPM per test as points, a rolling 10-test average as a second smoothed line, filters for
> mode and date range (7d/30d/90d/all), fully retthemed to `design-system.md` tokens, with the
> real-chart-shape shimmer loading state (never a blank box or bare spinner).

Test: view the chart with fewer than 10 tests (rolling average must degrade gracefully) and with
30+ tests. Commit.

### 15. Profile / dashboard

> **Prompt**
> Build a compact profile/dashboard view — personal-best WPM, all-time average WPM/accuracy, total
> tests taken, current streak — shown above or beside the speed curve on the history page. Keep it
> dense and glanceable, not a separate heavy page.

Test: set a new personal-best WPM, confirm the dashboard updates correctly. Commit.

### 16. Guest → account migration

> **Prompt**
> Build `POST /api/tests/import` per `api-conventions.md` and `ux-flows.md` Flow 4 — on signup or
> login, detect local-storage guest tests, import them, clear local storage, and show a toast with
> the exact imported count (never "some tests").

Test: take 3 tests as a guest, sign up, confirm the toast reads "Imported 3 tests" and they appear
in history. Commit.

### 17. Settings panel

> **Prompt**
> Build the settings page per `ux-flows.md`'s settings section — mode, duration/word-count,
> punctuation, and numbers toggles, all saving immediately with no Save button, persisted to local
> storage for guests and synced to `UserSettings` in the background for logged-in users.

Test: change a setting, reload, confirm it persisted; change it while logged in, then log in on a
second browser/session and confirm it synced. Commit.

### 18. Responsive & accessibility pass

> **Prompt**

### 25. Advanced analytics — accuracy trend, weak-key heatmap, consistency score

### 26. Custom text sources

### 27. Practice mode — weak-key drilling
